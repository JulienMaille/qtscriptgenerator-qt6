# Porting QtScriptTools to Qt 6 on Linux

This document details the step-by-step engineering process of porting the legacy **QtScriptTools** module (historically a part of Qt 5's `qtscript` module) to build and run under **Qt 6.8 LTS (6.8.0)** using CMake.

The `qtscript-qt6` companion repository provides the baseline port for `Qt6::Script` but previously excluded `Qt6::ScriptTools`. Below is the complete explanation of the modifications, architectural decisions, and bug-fixes implemented to bring `Qt6::ScriptTools` back to life.

---

## 1. Submodule Discovery & Analysis

In the original Qt 5 `qtscript` baseline, the `QtScriptTools` module resides in `src/scripttools/`, which contains a `debugging/` directory hosting all the debugger UI components, widgets, models, and execution controllers.

1. **Project files (`scripttools.pro`, `debugging.pri`):** We inspected the qmake files to catalog the required source files, headers, and UI resources.
2. **Target Dependencies:** The module requires private access to the internal structures of QtCore, QtGui, QtWidgets, and QtScript:
   * **Qt 5 qmake equivalent:** `QT = core-private; QT_PRIVATE = gui widgets-private script`

---

## 3. Resolving Qt 6 Architectural & API Incompatibilities

### A. Re-implementing `QScopedSharedPointer` (`qscopedpointer_p.h` removal)
In Qt 5, five header files within the debugger backend included the private header `<QtCore/private/qscopedpointer_p.h>` to use the internal class template `QScopedSharedPointer<T>`. In Qt 6, this header and template class were completely removed.

* **Analysis:** `QScopedSharedPointer` behaves like a reference-counting shared pointer for subclasses of `QSharedData` but without the copy-on-write characteristics. Standard `QSharedPointer` is a public header-only template in Qt 6, but `Q_DECLARE_PRIVATE` assertions expect `get() noexcept` and other manual reference-counting semantics.
* **Resolution:** We implemented a standard-compliant, drop-in replacement header `src/scripttools/debugging/qscopedsharedpointer_p.h`:
  ```cpp
  #ifndef QSCOPEDSHAREDPOINTER_P_H
  #define QSCOPEDSHAREDPOINTER_P_H

  #include <QtCore/qglobal.h>

  QT_BEGIN_NAMESPACE

  template <typename T>
  class QScopedSharedPointer
  {
  public:
      inline QScopedSharedPointer(T *ptr = nullptr) noexcept : d(ptr)
      {
          if (d) d->ref.ref();
      }
      inline ~QScopedSharedPointer() noexcept
      {
          if (d && !d->ref.deref()) delete d;
      }
      inline QScopedSharedPointer(const QScopedSharedPointer &other) noexcept : d(other.d)
      {
          if (d) d->ref.ref();
      }
      inline QScopedSharedPointer &operator=(const QScopedSharedPointer &other) noexcept
      {
          if (d != other.d) {
              if (d && !d->ref.deref()) delete d;
              d = other.d;
              if (d) d->ref.ref();
          }
          return *this;
      }
      inline void reset(T *ptr = nullptr) noexcept
      {
          if (d != ptr) {
              if (d && !d->ref.deref()) delete d;
              d = ptr;
              if (d) d->ref.ref();
          }
      }
      inline void assign(T *ptr) noexcept { reset(ptr); }
      inline T *data() const noexcept { return d; }
      inline T *get() const noexcept { return d; }
      inline T *operator->() const noexcept { return d; }
      inline T &operator*() const noexcept { return *d; }
      inline operator bool() const noexcept { return d != nullptr; }
      inline bool operator!() const noexcept { return d == nullptr; }
  private:
      T *d;
  };

  QT_END_NAMESPACE
  #endif
  ```
  We redirected all five header files to use this new compatibility layer.

### B. Correcting `QStringList` Forward Declarations
In Qt 6, `QStringList` is no longer a separate class. It was refactored into a `using` type alias (`using QStringList = QList<QString>;`).

* **Symptom:** Forward declaring it as `class QStringList;` raised:
  `error: using typedef-name 'using QStringList = class QList<QString>' after 'class'`
* **Resolution:** Replaced all six forward declarations of `class QStringList;` inside the module's headers with a clean inclusion of `<QtCore/qstringlist.h>`.

### C. Replacing Deprecated `QRegExpValidator`
* **Symptom:** `QRegExp` and `QRegExpValidator` are fully deprecated/removed in Qt 6.
* **Resolution:** Modified `debugging/qscriptbreakpointswidget.cpp` to use the standard Qt 6 `QRegularExpression` and `QRegularExpressionValidator` components, adding `#include <QtGui/QRegularExpressionValidator>`.

### D. Eliminating Outdated `QList::toSet()` and `QSet::toList()` Methods
In Qt 6, the `toSet()` and `toList()` conversion methods were removed.

* **Resolution:** Replaced all implicit/deprecated conversions across `qscriptdebuggeragent.cpp`, `qscriptdebuggercommandexecutor.cpp`, `qscriptobjectsnapshot.cpp`, and `qscriptxmlparser.cpp` with standard STL-style explicit range-based constructions:
  * **List to Set:** `QSet<T>(list.begin(), list.end())`
  * **Set to List:** `QList<T>(set.begin(), set.end())`

## 4. Modernizing RCC Compiled Resource Generation

The debugger requires its UI icons and commands loaded through `scripttools_debugging.qrc`. In Qt 6, compiled resources must be added formally to the target during project configuration.

* **Resolution:** Removed the `.qrc` source from the normal source file list and registered it using Qt 6's built-in CMake compiler tool:
  ```cmake
  qt_add_resources(ScriptTools "scripttools_debugging"
      FILES "debugging/scripttools_debugging.qrc"
  )
  ```
  This correctly generates the binary compiler output, resolves the linker symbols, and matches the expected `qInitResources_scripttools_debugging()` signature called inside `qscriptenginedebugger.cpp`.

The package builds flawlessly with high parallelism:
```bash
cmake --build /tmp/qtscript-qt6-build --parallel $(nproc)
cmake --install /tmp/qtscript-qt6-build
```
This correctly generates and registers the CMake targets, installs the public/private headers, and writes `libQt6ScriptTools.so.6.8.0` alongside its `qt_lib_scripttools.pri` descriptor directly under `/opt/qt6/6.8.0/gcc_64`.
